# 1688 搜索与商品判定

拿到 `tasks.json` 后执行。逐组做完再进下一组，每组结束立刻写 `findings/group-{NN}.json`。

## 1. 适配并准备浏览器

全程通过当前 Windows Agent 可用的**交互式浏览器控制能力**直接访问 1688.com。可使用内置浏览器、Chrome 控制、浏览器 MCP 或其他能让用户看到页面并保留登录态的工具；不要绑定某个产品的工具名称或 JSON 参数。不要用命令行抓取、curl、`Invoke-WebRequest` 或其他裸 HTTP 方式抓取 1688。

### 1.1 能力映射

开始前把下列语义动作映射到当前实际工具：

| 语义动作 | 最低要求 | 回退方式 |
| --- | --- | --- |
| 打开或导航 | 打开指定 URL，能继续复用当前会话 | 没有标签页标签时记录工具返回的页面或标签页标识 |
| 读取页面状态 | 能读取当前 URL、标题、可见内容和搜索结果图片或截图 | 只有截图时结合点击与地址栏 URL 逐项核实 |
| 分析结果图片 | 能查看商品卡片图片，识别可见型号文字、品牌标记和产品形态 | 没有图像理解能力或图片无法辨认时直接打开商品详情页，不按标题排除 |
| 操作页面 | 能使用当前页面提供的搜索、翻页、加载更多、打开结果和返回等交互 | 操作入口变化时重新观察页面并按语义定位，不复用旧引用 |
| 管理页面 | 优先复用两个固定标签页或页面 | 不支持多标签页时用单页导航，不得丢失待处理搜索词 |

工具使用循环保持为：**读取当前页面状态 → 执行动作 → 再次读取并验证结果**。页面变化后旧元素引用失效，就重新读取页面，不要沿用过期引用。

### 1.2 开跑前检查

1. 确认存在满足上表要求的浏览器工具；如果存在多个，优先选择能复用用户现有 Chrome 登录态或能显示窗口供用户手工登录的工具。
2. 查看当前页面或标签页，尽量复用已有的 1688 页面，避免重试留下大量窗口。不要读取、导出或记录 Cookie。
3. 为搜索页和详情页各保留一个固定页面；不支持多页面时使用单页模式，并在进入详情前记录搜索 URL 和进度。
4. 导航到 `https://www.1688.com`，读取当前 URL 与页面内容，确认是正常首页而不是 `login.1688.com`、滑块或人机验证页。
5. **未登录就停下来请用户在当前可见浏览器窗口里手工登录**，登录后重新读取页面状态再继续；不要脚本化绕过登录或验证码。

浏览器工具不可用、只提供无登录态的后台 HTTP、浏览器窗口无法让用户完成人工验证，或用户拒绝登录时：立即说明“无法打开 1688 搜索”和具体阻塞点，**不要**改用搜索引擎摘要、记忆里的商品或凭空生成候选。

## 2. 单组搜索流程

### 2.1 搜索

对该组按 `input-parsing.md` 第 4 节定下的深度，逐词串行搜索。使用 1688 当前页面可见的搜索入口提交原始关键词，并在每次提交后确认页面显示的搜索词与预期一致。

#### 中文关键词编码规则

- 使用 1688 页面搜索框时，直接输入报告中的原始中文关键词，不要先把 `%E9...` 形式的编码文本填进搜索框。
- 只有在浏览器工具需要构造带 `keywords` 参数的 URL 时，才把原始 Unicode 关键词做**一次 UTF-8 percent-encoding**。不要使用 GBK，不要手工替换字符，也不要对已经包含 `%` 编码的值再次编码。
- Windows PowerShell 使用 `[System.Uri]::EscapeDataString($term)`；编码后立即用 `[System.Uri]::UnescapeDataString($encoded)` 反向解码，必须与 `$term` 逐字符完全相同才允许导航。
- 例如 `飞利浦剃须刀底座` 应编码为 `%E9%A3%9E%E5%88%A9%E6%B5%A6%E5%89%83%E9%A1%BB%E5%88%80%E5%BA%95%E5%BA%A7`。其中 `浦` 是 `%E6%B5%A6`，`剃` 是 `%E5%89%83`；不要把它们误编码成 `流` 或 `剁`。
- 导航后再次核对页面展示的关键词。只要出现乱码、错字、截断或百分号文本，就停止读取结果，回到原始关键词重新编码并提交；异常关键词下的结果全部无效。

PowerShell 示例：

```powershell
$term = '飞利浦剃须刀底座'
$encoded = [System.Uri]::EscapeDataString($term)
if ([System.Uri]::UnescapeDataString($encoded) -cne $term) {
    throw '关键词 UTF-8 编码往返校验失败'
}
```

按页面当时提供的交互逐步查看更多结果，直到达到用户指定的抓取条数或页面没有更多结果。出现任何风控迹象时立即进入第 3 节的暂停与恢复流程，不得把风控当成本词结束并继续后面的词。不要写死搜索 URL、CSS 选择器、节点层级、按钮文案、滚动次数或分页方式。

从当前页面能直接确认的信息中记录候选，至少包括商品标题和用于打开商品的搜索结果链接；价格、店铺等页面未明确提供的字段记为“未提供”。搜索结果链接只用于导航，不直接写入最终报告。读取原则：

- 按“商品结果”“价格”“店铺”等页面语义识别信息，不依赖固定标签、class 名、属性名或相邻节点关系。
- 若浏览器工具能返回结构化页面信息，可使用它提高效率，但先抽查结果与可见页面一致；结构化读取失败时改为逐项打开候选核实，而不是临时编写绑定当前页面结构的解析脚本。
- 如果只能通过截图浏览，就逐个打开候选，再从商品详情页的当前页面或地址栏记录最终链接；不能根据标题、型号或猜测拼接 URL。
- 一个词搜完再搜下一个，**串行、不并发**，词与词之间不要连续猛刷。
- 优先按页面提供的稳定商品标识或完全相同的真实链接去重；取不到时按“店铺 + 标题”去重。不要假设商品编号存在于固定 URL 位置。
- `hits` 记录本次实际读取并可核实的结果数，不把页面模糊展示的总量估算当成精确命中数。

### 2.2 结合标题与搜索结果图片安排核实顺序

标题和搜索结果图片只用于判断“先核实哪个商品”，不得据此直接判定商品符合、不符合、兼容或不兼容，也不得据此把商品写进 `推荐`、`备选`、`待验证` 或明确的排除结论。

- 标题明确命中目标品类、品牌、型号或形态时，可优先打开详情页，但只把命中视为待核实线索。
- 标题未命中关键词、品牌或适配型号，或者标题信息不足时，**必须先查看该结果的商品图片**，不能直接降低优先级或排除。分析图片中可见的型号文字、品牌标记、包装标注、接口/结构和产品形态；即使文字较小，也尽量通过页面放大或清晰截图核对。
- 图片中出现目标型号、系列标记或疑似匹配形态时，提高该商品的详情页核实优先级，并记录看到的原始线索，例如“图片可见 S9000”“图片展示底座触点”；不要把 OCR 推测改写成确定事实。
- 图片没有显示型号、图片模糊、被遮挡或当前 Agent 无法分析图片时，结果仍然不能因标题未命中而排除。只要品类存在相关可能，就直接打开详情页核实。
- 图片分析应保持商品卡片与图片的一一对应。优先查看单个卡片或其清晰截图，避免把相邻商品图片、标题和链接混在一起。
- 未进入详情页的结果只能记为“未核实”，不能写成“不推荐”或用于证明 1688 没有合格商品。
- 搜索结果页上的价格、店铺、规格摘要同样只是线索，不能替代详情页证据。

### 2.3 强制核实商品详情页

对每个准备做出分级或明确排除结论的商品打开详情页，**不设置每组最多核实 3 个的上限**。优先用另一个固定标签页或页面，保留搜索结果页；只能使用单页时，先记录搜索 URL、搜索词和已处理位置，核实详情后返回。

从搜索结果进入详情页时按以下方式点击：

1. 重新读取当前页面，确认目标商品的标题、图片和卡片属于同一个结果。
2. 让目标商品图片完整或大部分进入可视区域，点击图片的**上半部分**，优先选择上半区中央。使用相对区域判断，不写死屏幕像素坐标。
3. 不点击图片下半部、图片底边或角落，避开可能覆盖其上的“找相似”、快捷操作、播放、收藏、角标和其他悬浮控件。
4. 点击后等待页面稳定；如果新开标签页或窗口，切换到新页面。确认当前页面确实是该商品详情页，而不是搜索页、快速预览、登录页、店铺页、图片页、错误页或中间跳转页。
5. 点击上半部分后没有导航时，重新读取卡片状态并在上半区中央重试一次；仍无法进入时，改用该卡片语义对应的商品链接。不要改点图片下半部分，也不要连续盲点。

确认方式以页面实际呈现的商品标题、商品信息和详情内容为准，不写死 URL 结构。若点击触发风控，立即执行第 3 节的暂停规则。

确认详情页后，读取浏览器当前最终 URL，原样记录为 `detail_url`。该地址才允许进入最终报告；搜索结果中的跳转地址只保留作内部导航，不得写进报告。若无法确认详情页或无法取得其最终 URL，该商品不得进入报告候选清单。

围绕本组判定所需的商品事实查找价格/阶梯价、起订量、店铺名、适配型号、尺寸、材质、接口/电压、是否含线、是否现货等信息。按字段含义识别，不假设这些信息位于固定区域、表格、标签页或节点中；必要时使用页面当前提供的展开、规格切换或查看更多等只读交互。

页面上没写的项一律记“未提供”，不要用常识、标题或搜索结果摘要补齐。为每个已核实商品记录 `detail_verified: true`，并逐条保存支持或否定 `must_have` 的详情页证据；无法正常打开详情页时不得对该商品做符合性结论。

不要为了筛选进入店铺页核实开店年限、地区、主营类目或是否支持定制/打样。即使页面顺带显示这些信息，也忽略它们，不用于候选筛选、分级、排序或“待确认”。

### 2.4 判定分级

只对照**本组**的 `real_need` 和 `must_have`：

| 等级 | 条件 |
| --- | --- |
| ✅ 推荐 | 已核实详情页 + 品类形态正确 + 每一条 `must_have` 都有详情页直接证据 |
| 🟡 备选 | 已核实详情页 + 品类形态正确，但有 1 条 `must_have` 在详情页缺少直接证据，或价格/起订/材质信息缺失 |
| ⚠️ 待验证 | 已核实详情页，方向基本正确，但适配型号、尺寸、接口等关键项仍需向卖家索要实测/图纸/样品 |
| ❌ 不推荐 | 已核实详情页，确认品类错误、适配对象冲突，或与 `must_have` 直接矛盾 |

数量：每组 `推荐` ≤ 3、`备选/待验证` ≤ 3。`不推荐` 不进清单，只概括**经详情页核实**的主要排除原因。未打开详情页的搜索结果不参与分级或排除统计。

**一个合格候选都没有时**，只有在已对具有相关可能性的商品完成详情页核实后，才能写“未找到合格商品”，并给出下一步方向（换搜索词 / 走替代品类 / 需要定制开发 / 该需求 1688 现货稀缺）。不能仅凭标题或搜索结果摘要得出零合格结论，也不要用勉强相关的商品凑数。

### 2.5 证据与兼容性口径

- 每个候选的 `detail_url` 必须来自本次搜索结果实际打开后、确认商品详情页身份时浏览器显示的最终 URL。不得把搜索结果跳转地址、店铺地址、图片地址或重定向中间地址当成详情页链接，也不得按猜测改写、规范化或拼接。
- 兼容性结论只接受详情页证据：`商品页明确列出的型号/规格` > `商品页中的卖家明确适配说明`。搜索页标题、图片文字、OCR 结果或产品外观只用于决定是否进入详情页，不属于最终证据，不能据此确认兼容或不兼容。
- 1688 标题里的“通用”“多型号适用”**不算兼容证明**；进入详情页后仍没有具体适配证据时，标为 ⚠️ 待验证。
- 尺寸、电压、接口这类参数，来自详情页要注明来源是详情页；没查到就写「未提供」，不要用常识补齐。
- 卖家在标题里写品牌名不代表有授权。涉及品牌配件（尤其是原报告已标出 IP 风险的组），在该组风险提示里保留授权/商标提醒。
- 起订量（MOQ）如实记录，但**不作为降级理由**，也不影响排序。

## 3. 风控与失败恢复

- **统一暂停规则** —— 页面出现登录、滑块、人机验证、访问受限、异常空白或疑似限流时，立即停止所有浏览器操作。把当前组、当前搜索词、已读取数量和下一步位置写入进度文件，状态记为 `paused_risk_control`；随后明确提示用户在当前浏览器窗口手工登录、完成验证或按页面提示处理。提示后等待用户确认，不继续下一个搜索词或下一组，也不生成正常完成报告。
- **用户确认处理完成后** —— 重新读取当前页面，确认正常结果可见，再把状态改回 `pending`，从被拦的同一搜索词和记录位置继续。若无法可靠衔接，可重新执行当前搜索词并按真实链接去重，但不得跳过该词。页面仍受限时继续保持暂停并再次如实提示，不自行宣称恢复。
- **多个不同关键词连续返回 0 条**，但页面没有明确提示 —— 按疑似反爬限流处理，而不是判定“1688 没有货”。暂停流程，请用户检查浏览器是否有验证或访问限制；必要时由用户决定稍后再继续。恢复后重新执行被拦的搜索词。**绝不能把限流导致的 0 结果写成“未找到合格商品”。**
- **单个冷门词返回 0，同批次其他词正常** —— 是词太窄。可以放宽一档（去掉型号后缀或改用同组另一个词）再试一次，然后如实记录。
- **搜索词在页面里显示成乱码、错字、百分号文本或被截断** —— 按第 2.1 节重新从原始 Unicode 关键词生成 UTF-8 percent-encoding，并通过反向解码校验后再提交；不要把异常关键词下的结果当有效数据。
- **元素引用失效 / 点击报错** —— 重新读取同一页面的可见内容或截图，按当前页面语义重新定位后再试一次；页面已经进入阻塞状态（验证、登录、报错页）就报告阻塞点，不要反复重试。
- **重试留下多余标签页** —— 用当前工具的页面管理能力关闭多余页面，尽量只保留搜索页和详情页；若工具不支持关闭，停止继续新建并复用现有页面。
- 任何失败或暂停都要落到 `findings/group-{NN}.json` 的 `status` 和 `note` 里。只有用户明确取消任务并要求部分报告时，才可把未恢复的风控位置写进部分报告；这不算正常完成。
