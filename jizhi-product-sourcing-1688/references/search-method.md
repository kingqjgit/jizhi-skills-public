# opencli 1688 搜索与商品判定

拿到 `tasks.json` 后执行。逐组做完再进下一组，每组结束立刻写 `findings/group-{NN}.json`。

## 1. 准备 opencli 环境

全程通过 [opencli](https://opencli.info/) 的 1688 浏览器适配器访问 1688.com（文档：<https://opencli.info/docs/adapters/browser/1688.html>）。该适配器要求本机 **Chrome 正在运行并已登录 1688.com**，且已安装并连接 **Browser Bridge** 浏览器扩展；opencli 通过这条通道复用真实登录态浏览器，不是裸 HTTP 抓取。不要用命令行抓取、curl、`Invoke-WebRequest` 或其他裸 HTTP 方式访问 1688，也不要绕过 opencli 直接调用其底层接口。

### 1.1 开跑前检查

1. 确认本机已安装 opencli，且 PATH 中可以直接执行 `opencli` 命令；可用 `opencli list` 确认适配器注册表可读、`1688` 适配器存在。
2. 确认 Chrome 正在运行、已通过 Browser Bridge 插件连接，并已登录 1688.com（不是 `login.1688.com` 或滑块/验证页）。这一步没有独立的“登录检查”命令，用本组第一条真实搜索词直接执行一次 `opencli 1688 search`，把它的结果当作环境自检：命令报错、返回空、或报错信息提示登录/验证/未连接时，视为环境未就绪。
3. 任一项不满足时：**停下来请用户处理**——安装/更新 opencli、安装并连接 Browser Bridge 插件、在该 Chrome 窗口手工登录 1688.com——不要改用搜索引擎摘要、记忆里的商品或凭空生成候选，也不要用无登录态的接口替代。

### 1.2 命令一览

| 命令 | 用途 | 常用参数 |
| --- | --- | --- |
| `opencli 1688 search "<query>" --limit <n> -f json` | 关键词搜索，返回商品列表（标题、价格/价格区间、起订量、店铺链接、offer_id 或商品链接、图片等，具体字段以实际输出为准） | `--limit` 默认 20，最高 100 |
| `opencli 1688 item <url-or-offer-id> -f json` | 单个商品详情：阶梯价、MOQ、发货信息、店铺基本信息 | 参数可传商品 URL 或 offer_id |
| `opencli 1688 assets <url-or-offer-id> -f json` | 该商品在详情页上可见的全部媒体（主图、变体图、详情图集、视频） | 用于标题/缩略图不足以判断时补充查看 |
| `opencli 1688 download <url-or-offer-id> --output <dir>` | 把该商品可获取的媒体批量下载到本地目录 | 仅在需要把图片存到本地才能查看/核对时使用，非默认步骤 |
| `opencli 1688 store <url-or-member-id> -f json` | 店铺/供应商信息（公司信息、入驻年限、主营类目、服务标识等） | 只用于记录风险提示背景，不用于筛选 |

所有命令都只读取或下载公开页面上可见的字段和媒体，不发询盘、不下单、不访问卖家后台——这是适配器本身的限制，也符合本 skill 的只读约束。

`-f json` 用于取得结构化输出；不确定某个字段叫什么名字时，先看一次真实返回的 JSON，按语义（标题、价格、起订量、商品/店铺链接、图片地址等）识别对应字段，不要假设固定字段名或格式，命令版本更新可能改变具体字段。

### 1.3 遇到机器人验证时必须停下来

抓取过程中随时可能触发 1688 的机器人验证（滑块、人机识别、短信/扫码验证、访问受限提示等）。这类验证**只能由用户在真实浏览器窗口里手工完成**，Agent 不得尝试识别、点击、模拟或以任何方式绕过验证控件，也不得换用无登录态的接口或第三方数据源替代。

识别信号（出现任一即视为触发验证，不要自行判断"应该没事"继续跑）：

- `opencli 1688 search` / `item` / `assets` 命令报错、超时，或退出码非 0；
- 命令返回内容不是预期的商品 JSON，而是提示登录、滑块、验证码、"访问异常"、"环境异常"等文字；
- 按 opencli 官方排障建议（<https://opencli.info/docs/adapters/browser/1688.html>）：`item`/`assets` 失败时应确认 Browser Bridge 控制的 Chrome 是否真的停在目标 `detail.1688.com` 商品页——如果窗口显示的是验证页而不是商品页，同样视为触发验证；
- 同一批不同关键词连续返回 0 条，且命令本身没有给出"无结果"的明确提示（这通常是风控降级而不是真的没货）。

处理步骤：

1. **立即停止**，不再发起下一条 `opencli` 命令（不换词、不换组、不重试同一条命令刷新等待）。
2. 把当前组号、当前搜索词或正在核实的商品、已完成到的位置写入 `findings/group-{NN}.json`，`status` 设为 `paused_risk_control`。
3. 明确告诉用户：命中疑似机器人验证，请切换到 Browser Bridge 控制的那个 Chrome 窗口，手工完成滑块/验证码/登录等操作；操作完成前 Agent 会保持暂停，不生成"正常完成"的报告。
4. 等待用户确认已处理完成后，按第 3 节「用户确认处理完成后」的流程，从被拦的同一条搜索词或商品重新发起**同一条**命令验证是否恢复，再继续后续流程。

## 2. 单组搜索流程

### 2.1 搜索

对该组按 `input-parsing.md` 第 4 节定下的深度，逐词串行执行：

```powershell
opencli 1688 search "<term>" --limit 40 -f json
```

- `<term>` 直接取自 `tasks.json` 中的原始搜索词，不做任何编码或改写。
- 一个词搜完、记录完结果再搜下一个词，**串行、不并发**，避免连续高频调用触发风控或占满同一个 Browser Bridge 会话。
- 解析返回的 JSON 列表，逐条读取标题、价格/价格区间、起订量、商品链接或 offer_id、图片地址等字段；页面/接口未提供的字段记为“未提供”，不要用常识补齐。
- **不要直接信任 `search` 返回的 `price_min`/`price_max`/`price_text` 数值字段**：实测中这些字段偶尔会从标题里的型号编号或"回头率 NN%"之类的文字中错误提取数字（例如标题含 `HQ8505` 时 `price_min` 被误取成 `8505`）。价格判断以标题里肉眼可见的 `¥` 金额文本为准，或用 `opencli 1688 item` 返回的 `price_text`/`price_tiers`（该字段实测更可靠）二次确认；不要把 `search` 阶段的价格数字直接写入报告。
- 优先按返回结果中的 `offer_id`（或等价稳定标识）去重；取不到时按“店铺 + 标题”去重。
- `hits` 记录本次命令实际返回并可读取的结果条数；命令本身返回条数少于 `--limit` 时按实际数量记录，不臆测总量。
- 命令报错、超时、返回空结果但没有明确“无结果”提示时，先怀疑环境或风控问题，进入第 3 节处理，不要当作“该词没有商品”直接跳过。

### 2.2 结合标题与搜索结果图片安排核实顺序

标题和 `search` 返回的图片（必要时用 `assets` 补充）只用于判断“先核实哪个商品”，不得据此直接判定商品符合、不符合、兼容或不兼容，也不得据此把商品写进 `推荐`、`备选`、`待验证` 或明确的排除结论。

- 标题明确命中目标品类、品牌、型号或形态时，可优先对该商品调用 `opencli 1688 item`，但只把命中视为待核实线索。
- 标题未命中关键词、品牌或适配型号，或者标题信息不足时，**必须先查看该结果的图片**，不能直接降低优先级或排除。能读取图片内容时，识别图片中可见的型号文字、品牌标记、包装标注、接口/结构和产品形态；`search` 返回的缩略图不够清楚时，用 `opencli 1688 assets` 取该商品更完整的图集再看。
- 图片中出现目标型号、系列标记或疑似匹配形态时，提高该商品调用 `item` 核实的优先级，并记录看到的原始线索，例如“图片可见 S9000”“图片展示底座触点”；不要把识别结果改写成确定事实。
- 图片没有显示型号、图片模糊、无法获取图片或当前 Agent 无法分析图片时，结果仍然不能因标题未命中而排除。只要品类存在相关可能，就直接对该商品调用 `item`。
- 未对某商品调用 `item` 核实的结果只能记为“未核实”，不能写成“不推荐”或用于证明 1688 没有合格商品。
- `search` 返回的价格、店铺、规格摘要同样只是线索，不能替代 `item`/`assets` 的详情证据。

### 2.3 强制用 `opencli 1688 item` 核实商品详情

对每个准备做出分级或明确排除结论的商品执行：

```powershell
opencli 1688 item <url-or-offer-id> -f json
```

- 优先使用 `search` 结果里携带的商品链接或 offer_id 作为参数；两者都拿不到该商品时，该商品不得进入报告候选。
- 命令成功返回后，从结果中确认这就是目标商品（标题、图片与 `search` 阶段看到的一致），再读取本组判定所需的商品事实：阶梯价/价格、起订量、发货信息、适配型号、尺寸、材质、接口/电压、是否含线、是否现货等。按字段含义识别，不假设这些信息位于固定字段名下；输出里没有的项一律记“未提供”，不要用常识、标题或搜索结果摘要补齐。
- 标题、图片信号仍然不足以判断某项 `must_have` 时，可再执行 `opencli 1688 assets <url-or-offer-id> -f json` 查看完整图集/视频列表，寻找更清楚的型号、接口或包装标注证据。
- 只有当 Agent 自身无法直接读取图片内容、必须落到本地文件才能查看时，才用 `opencli 1688 download <url-or-offer-id> --output <run_dir>\media\{offer_id}` 把媒体存到本次运行目录下再读取；这不是默认步骤，避免为每个候选都下载媒体。**注意**：`download` 会在 `--output` 目录下再新建一层以 `offer_id` 命名的子目录（即实际文件落在 `<output>\{offer_id}\{offer_id}_main_NN.jpg`），读取前用文件系统工具确认真实路径，不要假设文件直接落在 `--output` 指定的目录下。
- `opencli 1688 item` 命令失败、超时，或返回内容与该商品明显不符（标题/图片对不上）：先确认参数（URL/offer_id）是否取自本次 `search` 结果且未被误改；重新执行一次仍不符或仍失败，则该商品视为无法核实，不得据此下结论，也不得进入报告候选清单。
- 记录 `detail_verified: true`，并逐条保存支持或否定 `must_have` 的 `item`/`assets` 输出证据；无法成功取得该商品详情时不得对该商品做符合性结论。
- **`detail_url`（写进报告的唯一商品链接）**：优先取 `opencli 1688 item` 返回 JSON 中的规范商品链接字段（字段名以实际输出为准，例如 `url`/`detailUrl`/`item_url` 之类）。如果输出没有现成链接字段，可用 1688 详情页的标准地址格式 `https://detail.1688.com/offer/{offer_id}.html` 由该商品的 `offer_id` 拼出，但拼出后必须再用同一个 `offer_id`（或该链接）跑一次 `opencli 1688 item` 核对返回的确实是同一商品，才允许写入报告；否则该商品不得进入候选。
- 不要为了筛选去调用 `opencli 1688 store` 核实开店年限、地区、主营类目或是否支持定制/打样。即使顺带取得这些信息也忽略它们，不用于候选筛选、分级、排序或“待确认”；`store` 命令只在需要为风险提示补充背景（例如判断品牌授权风险）时才用，且不作为筛选依据。

### 2.4 判定分级

只对照**本组**的 `real_need` 和 `must_have`：

| 等级 | 条件 |
| --- | --- |
| ✅ 推荐 | 已用 `item` 成功取得详情 + 品类形态正确 + 每一条 `must_have` 都有 `item`/`assets` 输出的直接证据 |
| 🟡 备选 | 已用 `item` 成功取得详情 + 品类形态正确，但有 1 条 `must_have` 在详情中缺少直接证据，或价格/起订/材质信息缺失 |
| ⚠️ 待验证 | 已用 `item` 成功取得详情，方向基本正确，但适配型号、尺寸、接口等关键项仍需向卖家索要实测/图纸/样品 |
| ❌ 不推荐 | 已用 `item` 成功取得详情，确认品类错误、适配对象冲突，或与 `must_have` 直接矛盾 |

数量：每组 `推荐` ≤ 3、`备选/待验证` ≤ 3。`不推荐` 不进清单，只概括**经 `item` 核实**的主要排除原因。未成功调用 `item` 的搜索结果不参与分级或排除统计。

**一个合格候选都没有时**，只有在已对具有相关可能性的商品完成 `item` 核实后，才能写“未找到合格商品”，并给出下一步方向（换搜索词 / 走替代品类 / 需要定制开发 / 该需求 1688 现货稀缺）。不能仅凭标题或搜索结果摘要得出零合格结论，也不要用勉强相关的商品凑数。

### 2.5 证据与兼容性口径

- 每个候选的 `detail_url` 必须来自 `opencli 1688 item` 返回结果中的规范商品链接，或经该命令核对确认有效的详情页地址（见 2.3）。不得把 `search` 结果里的跳转/图片/店铺地址当成详情页链接，也不得按猜测改写、规范化或拼接后不做核对。
- 兼容性结论只接受 `item`/`assets` 输出中的证据：`商品详情中明确列出的型号/规格` > `商品详情中卖家明确写出的适配说明`。`search` 阶段的标题、图片文字、产品外观只用于决定是否进入 `item` 核实，不属于最终证据，不能据此确认兼容或不兼容。
- 1688 标题里的“通用”“多型号适用”**不算兼容证明**；`item` 详情里仍没有具体适配证据时，标为 ⚠️ 待验证。
- 尺寸、电压、接口这类参数，来自 `item`/`assets` 输出的要注明来源；没查到就写「未提供」，不要用常识补齐。
- 卖家在标题里写品牌名不代表有授权。涉及品牌配件（尤其是原报告已标出 IP 风险的组），在该组风险提示里保留授权/商标提醒。
- 起订量（MOQ）如实记录，但**不作为降级理由**，也不影响排序。

## 3. 风控与失败恢复

- **统一暂停规则** —— 命中 1.3 节列出的任一机器人验证/风控信号，或 `opencli 1688` 命令因 Browser Bridge 未连接、Chrome 未登录等环境问题失败时，按 1.3 节步骤立即停止所有后续命令、落盘暂停位置、提示用户手工处理。提示后等待用户确认，不继续下一个搜索词或下一组，也不生成正常完成报告。
- **用户确认处理完成后** —— 重新执行刚才失败的**同一条**命令（同一个 `term` 或同一个商品的 `url-or-offer-id`），确认这次返回正常的 JSON 数据后，再把状态改回 `pending`，从被拦的同一位置继续。若无法可靠衔接，可重新执行当前搜索词并按真实标识去重，但不得跳过该词。命令仍然失败或异常时继续保持暂停并再次如实提示，不自行宣称恢复。
- **多个不同关键词连续返回 0 条**，但命令本身没有报错或明确提示 —— 按疑似反爬限流处理，而不是判定“1688 没有货”。暂停流程，请用户检查 Chrome/Browser Bridge 是否正常、是否需要手工验证；必要时由用户决定稍后再继续。恢复后重新执行被拦的搜索词。**绝不能把限流导致的 0 结果写成“未找到合格商品”。**
- **单个冷门词返回 0，同批次其他词正常** —— 是词太窄。改用同组已有的下一项；没有备用项就如实结束该词，不新增词。
- **`item`/`assets` 返回内容与预期商品不符**（标题、图片对不上）—— 先确认传入的 URL/offer_id 是否确实来自本次 `search` 结果且未被误改；重新执行一次仍不符，则该商品记为无法核实，不参与分级，不写入报告。
- **命令报错提示 opencli 未安装、Chrome 未运行或 Browser Bridge 未连接** —— 属于环境问题：立即停止并如实说明具体报错，请用户检查本机 opencli 安装、Browser Bridge 插件连接状态和 Chrome 登录态；不得擅自改用其他抓取方式顶替。
- 任何失败或暂停都要落到 `findings/group-{NN}.json` 的 `status` 和 `note` 里。只有用户明确取消任务并要求部分报告时，才可把未恢复的风控/环境问题写进部分报告；这不算正常完成。
